Predicting Personal Loan Acceptance: A Data-Driven Strategy for Banks 🏦

Converting existing bank depositors into loan customers is a significant revenue opportunity, yet marketing campaigns can be costly and inefficient. This project presents a data science approach to pinpoint which customers have the highest probability of accepting a personal loan, enabling smarter, more targeted marketing efforts.

The Challenge: From Data to Decision

The analysis centers on a dataset from Thera Bank, which, like many financial institutions, wants to grow its loan business by marketing to its large base of deposit customers. With a previous campaign yielding a 9% conversion rate, the goal is to build a model that can significantly improve this result by identifying the right customers to target.

The project leverages a rich dataset of 5,000 customers, with attributes including demographics (`Age`, `Family` size), financial standing (`Income`, `CCAvg`, `Mortgage`), and their relationship with the bank (`CD Account`, `Securities Account`).

The Analytical Journey: Key Steps and Insights

This project follows a structured data science workflow, from cleaning the data to deploying a predictive model. Here’s a breakdown of the key stages and their outcomes:

1. Data Cleaning and Preparation

The initial step involved preparing the dataset for analysis. This included removing irrelevant columns like `ID`, converting categorical data (like `Education` and `Family`) into the correct format, and handling data inconsistencies. A notable finding was that 52 younger customers had negative values for `Experience`, which was determined to be a data entry error and corrected by taking the absolute value.

2. Exploratory Data Analysis (EDA) 📊

Before building the model, an exploratory analysis was conducted to uncover patterns in the data. This phase revealed which customer attributes were most correlated with loan acceptance.

  • Income is a Key Differentiator: The analysis showed a strong positive correlation between a customer's annual income and their likelihood of taking a personal loan.
  • Education Matters: Customers with higher education levels (Graduate or Advanced/Professional) were significantly more likely to accept a loan.
  • Other Financial Products: Having a Certificate of Deposit (CD) account with the bank was also a strong indicator of loan acceptance.

3. Building and Refining the Predictive Model ⚙️

Several machine learning models were trained to predict loan acceptance. The primary models used were Logistic Regression and a Decision Tree Classifier. The Decision Tree, a model that mimics human decision-making with a series of "if-then" questions, proved to be particularly effective.

To maximize performance, the Decision Tree was optimized using post-pruning. This technique simplifies the tree after it's built to prevent it from becoming too complex and "overfitting" the data, ensuring it can make accurate predictions on new, unseen customers.

The final, post-pruned Decision Tree model achieved an outstanding accuracy of 97% and a recall of 96%. High recall is especially valuable here, as it means the model successfully identifies 96% of all customers who would actually accept a loan, minimizing missed opportunities for the bank.

Getting Started with the Project

This analysis is contained within a single Jupyter Notebook (`model.ipynb`). To run it yourself, you would need a Python environment with standard data science libraries installed, including:

  • pandas for data manipulation
  • numpy for numerical operations
  • scikit-learn for building and evaluating the machine learning models
  • matplotlib and seaborn for data visualization

Conclusion and Usefulness 💡

This project demonstrates a powerful, practical application of machine learning in the financial sector. By building a highly accurate predictive model, Thera Bank can move from broad-stroke marketing to a precise, data-driven strategy.

The most influential factors in predicting loan acceptance were found to be Income, Education Level, and Family Size. By focusing marketing efforts on customers who fit this profile—such as those with higher incomes and graduate-level degrees—the bank can significantly increase its campaign conversion rates, boost revenue, and reduce marketing expenditure.

The methodology used here is not limited to personal loans; it can be adapted to predict customer interest in a wide range of financial products, such as mortgages, credit cards, or investment services, making it a valuable blueprint for any modern financial institution.

Building a Movie Recommender: From Simple Charts to Personalized Picks 🎬

Ever wonder how Netflix knows you’d love that obscure documentary? The magic is in recommender systems, a type of information filtering that has become the backbone of major tech companies. This project dives into the world of movie recommendations, building a series of engines that grow in complexity and performance.

The Goal: Solving the "What to Watch Next" Problem

This analysis uses the "TMDB 5000 Movie Dataset" to build a baseline movie recommender. The goal is not just to build one system, but to explore different strategies—from generic to personalized—to understand their strengths and weaknesses. The project serves as a foundational guide to the three main types of filtering techniques.

A Journey Through Recommendation Techniques

The project thoughtfully progresses through three distinct types of recommender systems, each with its own logic and outcomes.

1. Demographic Filtering: The "Top Charts" Approach

The simplest approach is to offer generalized recommendations based on a movie's popularity. This system doesn't know anything about you personally; it just assumes that a highly-rated, popular movie is a safe bet for any viewer. To do this fairly, the analysis uses the IMDB weighted rating formula, which balances a movie's average rating with the number of votes it has received.

Key Outcome: This method produces a reliable "Top 10" list of critically acclaimed films like The Shawshank Redemption, The Godfather, and The Dark Knight—great movies, but not personalized in any way.

2. Content-Based Filtering: The "If You Liked This, You'll Like That" Model

This is where recommendations start to get smarter. Content-based systems use a movie's metadata—like its genre, director, cast, and plot keywords—to find other movies that are similar. The project builds two versions:

  • Plot-Based Recommender: The first version analyzes only the movie's plot overview. It converts the text into numerical vectors using a technique called Term Frequency-Inverse Document Frequency (TF-IDF), which identifies the most significant words. It then uses cosine similarity to find movies with the most similar plot vectors.
  • Metadata-Rich Recommender: The second, more powerful version creates a "metadata soup" by combining the top 3 actors, the director, genres, and keywords. This captures more nuanced similarities. For instance, it recognizes that fans of one Christopher Nolan film might enjoy his other works, regardless of plot.

Key Outcome: When recommending based on The Dark Knight Rises, the metadata-rich recommender correctly suggested other Christopher Nolan films like The Dark Knight, Batman Begins, and even Inception, proving its superior performance.

3. Collaborative Filtering: The Power of the Crowd 👥

The most advanced technique explored is collaborative filtering. This system doesn't rely on movie metadata at all. Instead, it makes recommendations by matching people with similar tastes. The project uses a powerful method called Single Value Decomposition (SVD) to predict a user's rating for a movie they haven't seen. SVD uncovers latent (hidden) factors in user ratings to make these predictions.

Key Outcome: Using the surprise library, the SVD model was trained on a user-ratings dataset and achieved a Root Mean Square Error (RMSE) of approximately 0.89, which is a strong result. It could then predict a rating for a specific user and movie—for example, estimating a rating of 2.57 for user ID 1 on movie ID 302.

Getting Started with the Project

This entire analysis is built within a Python notebook. To explore or replicate the project, you would need an environment with the following key libraries:

  • pandas for data handling.
  • scikit-learn for its TfidfVectorizer, CountVectorizer, and cosine_similarity functions.
  • surprise for implementing the SVD-based collaborative filter.
  • matplotlib for visualizations.

The full code, showing each step from data cleaning to model evaluation, can view the project on GitHub.

Conclusion and Usefulness 💡

This project provides an excellent, step-by-step introduction to the fundamental concepts behind recommender systems. It clearly illustrates the trade-offs between simplicity and personalization, showing how adding more complex data and algorithms can lead to far more intelligent and useful recommendations.

The key takeaway, as noted in the notebook, is that the most powerful systems are often hybrid systems. By combining the metadata-awareness of content-based filtering with the crowd-sourced intelligence of collaborative filtering, platforms can overcome the limitations of any single approach. This project serves as a perfect foundational framework for anyone looking to build such a system.

Building a Real-Time Car Counter with YOLO and SORT 🚗

Manually counting objects is tedious and prone to error. This computer vision project offers a robust, automated solution for counting cars in a video feed, showcasing how modern machine learning models can be combined to create powerful, real-world applications.

The Goal: Automating Traffic Analysis

The project's primary objective is to process a video of a busy road and accurately count the number of vehicles that cross a designated line. To achieve this, it must not only detect vehicles in every frame but also track them to ensure each one is counted only once. This requires a sophisticated, multi-stage pipeline that brings together cutting-edge tools for detection and tracking.

The Core Components: A Two-Step Process

The system's logic is elegantly divided into two main tasks: identifying the objects and then tracking their movement over time.

1. Object Detection with YOLOv8

The foundation of the system is its ability to "see" the cars. For this, the project uses YOLO (You Only Look Once), a state-of-the-art, real-time object detection model. The script specifically loads the `YOLOv8m` (medium) weights, which provide a great balance between speed and accuracy. In each frame of the video, YOLO identifies all objects it recognizes—such as cars, trucks, and motorbikes—and draws a bounding box around them.

2. Object Tracking with SORT

Simply detecting cars in each frame isn't enough; you'd end up counting the same car multiple times. This is where the SORT (Simple Online and Realtime Tracking) algorithm comes in. The `sort.py` file provides the logic for this tracker. SORT takes the detections from YOLO and assigns a unique ID to each vehicle. It then uses a Kalman Filter to predict the car's position in the next frame, allowing it to maintain the same ID for the vehicle even if its appearance changes slightly. This persistent tracking is the key to accurate counting.

3. The Counting Mechanism

With vehicles detected and tracked, the final step is the count itself. The script draws a virtual line across the road on the video frame. It then continuously checks the center coordinates of each tracked vehicle's bounding box. When a vehicle's center point crosses this line, the system increments a counter and stores the vehicle's unique ID to ensure it is never counted again. The running total is then displayed on the screen for a real-time tally.

Getting Started with the Project

To run this project, you would need a Python environment with several key computer vision libraries installed:

  • ultralytics for access to the YOLO model.
  • opencv-python (or cv2) for video processing and drawing.
  • cvzone as a helper for drawing stylish bounding boxes.
  • The sort.py script must be present in the project directory, as it's a critical dependency for the tracking logic.
  • A video file containing cars or other objects to be tracked.

Conclusion and Broader Applications 💡

This project is a fantastic demonstration of how to build a practical computer vision application by intelligently combining specialized tools. The pairing of YOLO's powerful detection capabilities with SORT's efficient tracking creates a system that is both accurate and performant.

If you want to see the code, you can go to the GitHub repo.

While this implementation focuses on counting cars, the underlying framework is incredibly versatile and can be adapted for a wide range of use cases across different industries:

  • Retail Analytics: Counting the number of customers entering a store to analyze footfall, or monitoring queue lengths to improve staffing.
  • Industrial Automation: Counting products on a conveyor belt for quality control and inventory management.
  • Security and Surveillance: Monitoring a restricted area and counting the number of people who enter or leave.
  • Wildlife Conservation: Tracking and counting animals in their natural habitat to conduct population studies without human interference.
  • Smart Cities: Analyzing pedestrian flow in public spaces to optimize urban planning or monitoring the number of cars entering a parking garage.

Ultimately, any task that requires counting moving objects in a video feed can benefit from this robust and adaptable solution.
